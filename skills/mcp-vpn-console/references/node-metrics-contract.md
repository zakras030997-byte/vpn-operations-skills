# Контракт происхождения и актуальности метрик узла

Используй при многоузловом отображении в Telegram/API или сопоставлении снимков. Это общий контракт нормализации, не описание уже установленного endpoint, нового агента или разрешение на сбор/изменение сервера. Существующие API адаптируй явно; не требуй смены wire-формата. Ручные отчёты остаются допустимыми источниками.

## Идентичность и время

Для снимка и каждой группы показателей сохраняй безопасные сведения:

| Поле | Смысл |
| --- | --- |
| node_id | Узел, состояние которого измерено; связь с актуальным реестром, без вечных IP/ID чатов |
| origin_host и scope | Фактический хост измерения и область: host, container, controller или remote_api; технический адрес публично показывать не требуется |
| source | Метод/компонент получения и версия контракта при наличии; не credentials и не сырые секретные конфигурации |
| captured_at | Время самого измерения с часовым поясом; для CPU/скорости также начало/конец окна |
| received_at | Время получения центром; не заменяет captured_at |
| freshness | fresh / stale / unknown по явно указанному допустимому возрасту группы; источник этого предела — политика сервиса/назначенного цикла |
| availability | available / partial / unreachable / not_configured / not_tested с причиной и областью покрытия |

Названия полей логические: при ином формате сохраняй соответствие. Нельзя приписывать RAM/CPU хоста центрального remote-controller региональному VPN-узлу. Метрики контейнера маркируй отдельно от хоста. У ресурса, протокола, трафика и backup могут быть разные времена и freshness. Для агрегата показывай диапазон исходных времён; время формирования экрана не омолаживает данные. При неизвестном времени или неверных часах freshness неизвестна, пока причина не проверена.

Числовые методики, единицы, состояния контейнеров, новые рестарты и уровни проверки протоколов определены один раз в [формате v1.1](../../vpn-daily-quick-scan/references/report-format.md). Используй относящиеся поля; пропуск не заменяй нулём. not_configured означает доказанное отсутствие настройки, unreachable — недоступность источника, а не доказанное падение VPN. Свежая ресурсная метрика не подтверждает VPN-трафик. Счётчики учёта и live-скорость различай; replay регулируется [контрактом переноса учёта](../../vpn-service-maintenance/references/control-plane-migration.md).

## Потребители данных

- Telegram-панель: проверяй владельца/роль при каждом callback. Обновление выбранного узла имеет ограниченное ожидание; для одновременных одинаковых запросов допустимо использовать один запрос в работе. Отказ одного источника не блокирует остальные кнопки и очередь бота. При повторном нажатии покажи актуальный статус запроса, не запускай неограниченные повторы.
- При сбое допустимо показать последний разрешённый снимок с его captured_at, возрастом и ошибкой обновления. Не показывай его как свежее подтверждение нормы. Кеш соблюдает ту же авторизацию и не смешивает узлы/области. Пределы ожидания и кеша задай явно по текущему сервису; отсутствие настройки обозначь как пробел.
- Ежедневный скан и сводка используют ту же семантику происхождения; их назначенные объём, формат и правила исправлений сохраняются. Контракт не требует нового скана ради форматирования готового отчёта.
- Используй существующий разрешённый защищённый connector/API с проверкой узла и минимальными правами чтения. Добавление endpoint/агента, открытие портов и смена авторизации — отдельные изменения. Панель состояния не выполняет рестарт, выдачу доступа, изменение квот или платежей.

## Проверка при внедрении отображения

Сверь привязку каждой карточки к физическому источнику; проверь старый кеш, недоступный узел, неизвестное время и частичный ответ. В Telegram дополнительно проверь повторный callback, отказ одного источника и доступ постороннего пользователя. Проверка контракта или макета не является установленной реализацией и не заменяет реальную проверку Telegram.
