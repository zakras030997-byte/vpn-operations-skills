# VPN Operations Skills

Шесть переносимых скиллов Codex для безопасной эксплуатации VPN и переноса Telegram-бота. Инструкции на русском языке. Лицензия MIT.

Это публичная адаптация процедур, а не исходный код VPN-ядра, Telegram-бота или серверного агента. Репозиторий не содержит production-конфигураций, данных клиентов, адресов серверов, секретов, внутренних отчётов или истории частного проекта.

## Состав

| Скилл | Ответственность |
| --- | --- |
| vpn-telegram-bot-migration | Подготовка, переключение и восстановление Telegram-бота; сохранность очереди и проверка реальных ответов |
| vpn-service-maintenance | Подписки, общий учёт и перенос центрального управления |
| mcp-vpn-console | Инвентаризация и единый контракт происхождения метрик |
| vpn-admin-task-dispatch | Точное поручение существующему администратору и приёмка результата |
| vpn-daily-quick-scan | Ограниченная проверка назначенного узла и отчёт v1.1 |
| vpn-server-summary | Общая сводка по готовым источникам без повторного скана |

Общий контракт метрик и формат отчёта хранятся по одному разу. Скиллы не устанавливают runtime, не предоставляют серверный доступ и не разрешают изменения сами по себе.

## Установка

Скопируйте шесть папок из `skills/` в каталог скиллов вашей среды Codex, сохраняя имена и относительные ссылки. Перед заменой одноимённых локальных скиллов сравните их: эта публичная редакция не содержит частных профилей и настроек уведомлений.

Подготовьте собственный реестр узлов, доверенные host keys, ограниченные connectors и согласованные полномочия. Реальные секреты храните вне репозитория. Для координации нужны разрешённые средства адресации существующих задач; для клиентской приёмки — доступ к Telegram/VPN-клиенту. Без этих инструментов скилл должен сообщить конкретный недостающий вход.

Примеры: «Подготовь безопасный перенос бота, без изменений»; «Сверь свежесть метрик узла»; «Сделай общую сводку по этим отчётам».

## Проверка

Структура скиллов проверяется стандартным `quick_validate.py` среды Codex. Проверьте относительные ссылки и поведение на ваших схемах очередей, данных и доступа. Проверка инструкций не доказывает внедрение или исправность production-системы.

Не переносите старую БД поверх новых платежей, выдач или квот; не повторяйте неопределённые внешние операции вслепую. HTTP 200 и running не заменяют проверку реальной пользовательской функции.
